# Markdown — implementation plan

Spec: `docs/superpowers/specs/2026-11-04-markdown-design.md`, approved 2026-11-04. Work happens on
`feat/markdown`, which holds the spec. Each task writes its test first and sees it fail. It is
done when `./run check` passes, and it ends in one commit holding the test and the code. Merge by
rebase onto `main`, then `git merge --ff-only`.

The open issues were read before planning. #8 is this slice. #5, "WebKit is not run", covers it
as it covers the rest; #2, #3 and #4 touch other components. Core's #13, raised while specifying,
holds task lists.

## Decisions this plan adds to the spec

- **Core 0.3.0 comes in with the component.** Raising the dev dependency alone fails the contract
  test — core's new `prose.html` has no rows file — so the peer range, the dev dependency, the
  rows file and the component are one commit, as the architecture's release rule says. That
  commit closes #8.
- **The README's install pair moves at the release**, not before: it names a binding tag with
  each core tag, and binding 0.2.2 does not admit core 0.3.0.
- **What reaches the DOM is decided in `react-markdown`'s `components`**: `a`, `img`, `code`,
  `th`, `td`, `table` and `pre`. Each drops the `node` prop `react-markdown` passes. Its default
  `urlTransform` stays on, so a `javascript:` `href` arrives empty and fails the scheme check as
  well.
- **Two remark plugins in `src/markdown.tsx`**: one adding the GFM table syntax and its mdast
  conversion to the processor's data, one moving headings by `headingLevel`. The tree is walked
  by hand; no `unist-util-visit` dependency for a dozen lines.
- **`@types/mdast` is a dev dependency**, for the plugins' types; nothing exported names it.
- **The playground's Markdown section is `playground/sections/markdown.tsx`**, placed after Tabs.
